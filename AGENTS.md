# fishjam_client — guide for contributors and AI agents

Flutter (iOS + Android) client SDK for Fishjam. Behavior is defined in [SPEC.md](SPEC.md); read the sections
for the module you touch before writing code. Golden message sequences live in `test/fixtures/`.

## Commands

The toolchain (Flutter, protoc) is pinned in `mise.toml`. Prefix every command with `mise exec --`.

| Task | Command |
|---|---|
| Install dependencies | `mise exec -- flutter pub get` |
| Analyze (must be clean) | `mise exec -- flutter analyze --fatal-infos` |
| Format check | `mise exec -- dart format --output=none --set-exit-if-changed .` |
| Tests | `mise exec -- flutter test` |
| Coverage gate (≥ 90 %) | `mise exec -- flutter test --coverage && tool/check_coverage.sh` |
| Regenerate protobuf bindings | `mise exec -- tool/gen_protos.sh <path to a fishjam-cloud/protos checkout>` |
| Build the example app (iOS simulator) | `cd example && mise exec -- flutter build ios --simulator --no-codesign` |
| Integration tests (running Fishjam server) | `tool/run_integration.sh` (see `example/integration_test/README.md`) |

Run analyze, format and tests before every commit.

## Rules

- **Red-green TDD is mandatory.** Write the test first, run it and observe it fail, then implement, then see
  it pass. Do not skip the observed failure.
- **Spec first.** Behavior changes start in `SPEC.md` (and the affected fixtures), then tests, then code.
  Cite a section (`SPEC §N`) in a comment only where it explains a rule the reader would otherwise question.
- **Respect module boundaries** (see [Modules](#modules)). Shared seams (`rtc/rtc_adapter.dart`,
  `rtc/rtc_types.dart`, `signaling/transport.dart`, `models/`, `wire.dart`, `logger.dart`) change only
  together with every module that uses them.
- **Comments say what the code cannot.** Document the exported API concisely (behavior, units, errors,
  lifecycle). Elsewhere, comment only the why: protocol and platform quirks, invariants, ordering and
  concurrency rules. No comments that restate a name or signature (`public_member_api_docs` is off for
  this reason).
- **`flutter_webrtc` only at the boundary.** Only the adapter (`lib/src/rtc/flutter_webrtc_adapter.dart`, whose
  parts are `flutter_webrtc_adapter_*.dart`), the public models (`lib/src/models/`) and the facade
  (`lib/fishjam_client.dart`, `lib/src/fishjam_client.dart`, `lib/src/livestream_api.dart`) may import it. The internal modules (`signaling`, `engine`, `tracks`, `data`,
  `stats`, `livestream`) stay pure Dart on the `RtcAdapter` / `RtcMediaTrack` seam and are tested with
  `test/fakes/`; they must not import the adapter either. Convert with `wrapNativeTrack` / `nativeTrackOf` at
  the boundary (SPEC §20a). `test/import_boundary_test.dart` enforces this.
- **Never hand-edit `lib/src/proto/`.** It is generated by `tool/gen_protos.sh` and excluded from analysis and
  coverage. The minimum compatible protos revision is recorded in the script.
- **Logging:** use the single `FishjamLogger` passed to your module (`debug`, `warn`, `error`). It prefixes
  lines with `[FISHJAM]`, logs only when the client was created with `debug: true`, and writes through
  `dart:developer`. Never use `print`.
- **Metadata JSON is never empty.** Encode with `encodeMetadataJson` (`null` → `"null"`), decode with
  `decodeMetadataJson` (SPEC §2.3).
- **Errors in the media event loop never escape.** Unknown ids are logged and ignored (SPEC §7).
- **New library files** must be loaded by at least one test: `tool/check_coverage.sh` fails for a file under
  `lib/` with no coverage record.
- **This repository is public.** Do not reference private infrastructure, private repositories, internal
  service names or server implementation details in code, comments, tests, commit messages or PRs. Describe
  server behavior only as observable protocol behavior.

## Modules

| Directory | Responsibility |
|---|---|
| `lib/src/rtc/` | `RtcAdapter` seam and its `flutter_webrtc` implementation; no SDK logic |
| `lib/src/signaling/` | socket, auth, close reasons, message queue, reconnection; knows nothing about WebRTC |
| `lib/src/engine/` | per-session media event dispatch, negotiation state machine, command queue, peer connection, ICE |
| `lib/src/tracks/` | local/remote track state, simulcast encodings, bandwidth, variants, VAD, local audio level; never drives negotiation |
| `lib/src/data/` | reliable/lossy data channels and `ChannelMessage` framing |
| `lib/src/stats/` | periodic stats report |
| `lib/src/livestream/` | WHIP/WHEP over plain HTTP, independent of the room connection |
| `lib/src/audio_output/`, `lib/src/background/` | Dart side of the SDK's native plugin: audio routing, Android foreground service, iOS CallKit |
| `lib/src/models/`, `wire.dart`, `logger.dart`, `version.dart` | public immutable types and shared helpers |
| `lib/src/fishjam_client.dart`, `lib/src/livestream_api.dart`, `lib/fishjam_client.dart` | the public facade; wiring and type conversion only |
| `lib/src/connectivity_network_source.dart` | the `NetworkSource` (`signaling/network_source.dart`) on `connectivity_plus`; the only file that imports it |
| `test/fakes/`, `test/support/`, `test/fixtures/` | fakes, fixture replayer, golden sequences |

## Testing tools

- `test/fakes/fake_rtc.dart` — `FakeRtcAdapter` / `FakePeerConnection`: records every call (`calls`,
  `callsOf`), assigns mids on `setLocalDescription`, returns snapshot transceivers (re-fetch after
  `setLocalDescription` to read mids), and lets tests emit tracks, candidates, state changes and data channel
  events. `failNext(method, error)` scripts failures.
- `test/fakes/fake_transport.dart` — `FakeTransport` / `FakeTransportFactory`: records sent frames,
  `nextSent()`, `receive(PeerMessage)`, `serverClose(code:, reason:)`, `loseConnection()`.
- `test/support/fixtures.dart` — `Fixture.load(name)` and `FixtureReplayer` replay a golden sequence against a
  client wired to the fakes; `describeEvent` gives the JSON form of events used by `expect` steps. The step
  format is in SPEC §23.

## Dependencies

`pubspec.lock` is committed on purpose: it pins `protoc_plugin`, so `tool/gen_protos.sh` produces identical
bindings on every machine and in CI.

## Versioning

The package version follows the Fishjam web SDK release train (lockstep). `lib/src/version.dart` must equal
`version` in `pubspec.yaml` (a test enforces it); the `sdkVersion` sent on authentication is
`flutter-<version>`.
